# Meta: Token Optimization

## When to use

- Writing or editing any SKILL.md and checking it fits the 2000-token gate.
- Moving detail from SKILL.md into `references/` to cut activation cost.
- Reviewing a skill whose activation cost approaches the limit.
- Avoiding duplication between SKILL.md, references, and examples.

## When not to use

- Editing `references/` or examples (their cost is lazy, not activation).
- A one-off internal analysis with no skill artifact.
- If the skill already passes the gate and nothing changed — re-measuring is
  cheap but only needed after edits.

## What the agent often gets wrong

- B8/B9: writing "complete" skills that duplicate knowledge already in
  references or in another skill's references.
- Treating "under 2000" as a ceiling to approach instead of a floor to defend
  — activation cost should stay well below, since the gate is a hard CI error.
- Forgetting that metadata (name + description) counts toward activation cost.
- Editing body text without re-running `token_measure.py --check 2000`.
- Confusing activation cost (SKILL.md only) with total skill size (references
  + examples), and over-optimizing the wrong file.

## How to reason correctly

1. Measure before editing: `python tools/tokens/token_measure.py --check 2000
   skills/_meta/<skill>`.
2. Classify content: what must the agent see at activation (rules, triggers,
   verification commands, failure modes) vs what can wait (deep tables,
   per-tool details, long examples) — that is `references/`.
3. Move, do not copy: the reference file replaces the section; duplication
   bloats both SKILL.md and the reference and rots on edits.
4. Cross-check other skills: if the knowledge already lives in another
   skill's references, cite/cross-link instead of re-embedding.
5. Re-measure after every edit; keep a small margin (target ≤ 1700–1800).

## What to verify

- `token_measure.py --check 2000` exits 0 for the skill.
- SKILL.md body ≤ 250 lines and frontmatter description ≤ 50 words
  (`skill_lint.py` errors above those).
- No section in SKILL.md duplicates a reference file verbatim.
- Every removed section is actually represented in a reference (no knowledge
  silently lost).

## How to verify

```
python tools/tokens/token_measure.py skills/_meta/meta-token-optimization
python tools/tokens/token_measure.py --check 2000 skills/_meta/meta-token-optimization
python tools/lint/skill_lint.py skills/_meta/meta-token-optimization/SKILL.md
python tools/validate.py
```

## Where the knowledge comes from

- `tools/tokens/token_measure.py` (measurement backend, hard-limit mode).
- `tools/lint/skill_lint.py` (body ≤ 250 lines, description ≤ 50 words).
- `docs/architecture.md` (progressive disclosure design).
- `registry/evals.yaml` (calibration_notes — noise floor, not token budget).

## Evaluation

- Synthetic: given a bloated SKILL.md (fixture generated by
  `examples/bad/bloat_fixture.py`), the agent must move depth to references
  and re-measure under the gate.
- False-positive: a compact skill near but under the limit must not be
  "optimized" into losing required sections.
- Adversarial: a skill whose activation cost silently rose past 2000 after an
  edit must be caught by re-measuring (CI gate).
- Historical: the repo's own 124 skills passed the token gate (worst 1689,
  recorded in progress.yaml); regression runs keep it that way.
